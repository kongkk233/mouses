# 管理员与测试环境

生产站为 `mouses.ninthflux.com`，测试站为 `mouses-test.ninthflux.com`。二者使用独立服务、代码版本和数据库。

## 登录与切换

1. 打开生产站的 `/admin`，登录身份默认是“管理员 admin”。
2. 输入独立管理员密码。原访问密码继续用于“小窝访问”，不会因此取得管理员权限。
3. 控制台显示生产与测试的运行状态、版本、部署时间和通知状态。
4. 点击“进入测试环境”，新标签页自动确认生产管理员身份，在测试域建立独立会话，无需再输入密码。
5. 测试页面顶部、浏览器标题、表单标题和 PWA 名称均带测试标识。顶部“管理控制台”返回生产控制台。

管理员凭据由服务器生成并保存在受限环境文件中；本机管理员访问说明位于被 Git 忽略的 `data/admin-access.txt`。不要把密码、签名私钥或完整备份提交到 Git。

管理员会话为 12 小时，退出当前环境后撤销对应会话；另外一个环境的会话保持独立。已登录的普通用户可直接访问 `/admin`，重新输入管理员凭据升级身份。

## 环境结构

| 项目 | 生产 | 测试 |
| --- | --- | --- |
| 服务 | `mouse-nook.service` | `mouse-nook-test.service` |
| 本机端口 | `18326` | `18327` |
| 系统账户 | `mouse-nook` | `mouse-nook-test` |
| 代码与发布 | `/srv/mouse-nook` | `/srv/mouse-nook-test` |
| 数据库目录 | `/var/lib/mouse-nook` | `/var/lib/mouse-nook-test` |
| 受限配置 | `/etc/mouse-nook.env` | `/etc/mouse-nook-test.env` |
| 手机推送 | 按生产设置运行 | 强制关闭 |
| 内存限额 | 256 MiB | 256 MiB |
| CPU 限额 | 单核 50% | 单核 25% |

测试账户无法读取生产数据库、生产环境文件或生产发布目录。测试端只有验证登录凭据的公钥，不能签发生产登录凭据。普通访问凭据、管理员会话和生产 Cookie 均不能直接用于测试域。

首次建立测试库时导入独立示例资料。日常代码更新保留各环境数据，测试数据不会自动同步到生产。

## 开发、验收与发布

本地开发继续使用 Vite 热更新。需要自定义本地管理员时，在启动进程中分别设置不同的 `APP_PASSWORD` 和 `ADMIN_PASSWORD`，不要将真实线上密码用于本地调试。

```sh
npm run dev
```

修改完成后提交代码，先发布测试环境：

```sh
npm run build
npm test
git add <本次修改文件>
git commit -m "说明本次功能"
git push
./scripts/deploy.sh oracle mouses-test.ninthflux.com staging
```

在控制台进入测试站，使用测试资料验收。测试通过后，将同一代码提交发布生产：

```sh
./scripts/deploy.sh oracle mouses.ninthflux.com production
```

每个环境都在自己的发布目录构建、运行自动化测试，再切换 `current`。生产切换前生成数据库备份，激活后检查认证健康并再次备份；健康检查失败会切回该环境的上一版本。测试与生产允许运行不同提交，控制台会显示实际生效版本。

```sh
./scripts/rollback.sh oracle staging
./scripts/rollback.sh oracle production
```

回退代码不会回退数据库。数据库结构变更需另外设计兼容迁移；当前新增的管理员会话表和一次性凭据记录不修改业务模型及架构版本。

## 第一版范围

已实现管理员权限、双环境入口、浏览器绑定的一次性登录、版本与状态显示、测试标识和部署隔离。功能开发仍通过本地源码与 Git 完成，测试环境用于验收和调试业务行为。

网页源码编辑、错误日志浏览、测试数据一键重置、生产数据复制和网页一键发布可后续独立增加。当前没有通过管理页面覆盖数据库的操作。
